# Decisions — Pocket RAG / OKF

One row per call actually visible in the code. The rationale is the reason, not
a restatement of the behaviour. `design_theory.md` explains the principles these
came from and cites rows as `(#n)`.

This ledger starts over at #1: the app it was converted from was a GitHub repo
assistant, and none of that ledger survives the deletion of the git layer.

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | Keep Flutter/Dart; do not rebuild on open-webui's SvelteKit + Python stack | open-webui is a server app with a browser front end. This one has to run with the aeroplane mode switch on: inference, embeddings, index and store all on the handset. Porting to Svelte would mean re-solving the only hard part already solved here — the `llama_cpp_dart` FFI path and its pinned `llama.cpp` build (`docs/on_device_load_hang_rootcause.md`) — for no gain. |
| 2 | Take open-webui's *look* as reference, not its code | The `open-webui/` checkout in this repo is reading material. What was actually adopted is one interaction idiom in `chat_screen.dart`: a flat transcript where the user's turn is a soft rounded bubble and the assistant's is unbubbled body text with its metadata attached below. Nothing was copied. `app_theme.dart` was unchanged at the time, so this row was only ever about the transcript idiom, not the theme — **superseded on that point by #40**, which replaced the visual system outright from an imported design canvas. The transcript idiom survived the replacement. |
| 3 | OKF is a file format; both modes read one corpus | OKF ships no runtime and no index, so "OKF mode" is this app's graph-walk consumer of the format (`lib/retrieval/graph_retriever.dart`), not something OKF provides. Two corpora would mean two indexing paths, two staleness rules, and two chances to answer from a stale one. `Corpus` (`corpus.dart`) holds one bundle and every index over it. |
| 4 | In-memory BM25 (`keyword_index.dart:KeywordIndex`) instead of SQLite FTS5 | `ponytail:` — under ~5k documents a Dart inverted index answers in a few hundred microseconds and removes `sqflite` outright. **Ceiling:** RAM-resident and rebuilt on every open. Above ~5k documents, or when open time is felt, swap in `sqflite` + an FTS5 virtual table behind the same `search` signature. |
| 5 | Flat cosine scan (`vector_index.dart:VectorIndex`) instead of `sqlite-vec` or ObjectBox | `ponytail:` — 5k chunks × 384 dims is a few million multiplies, under 10 ms. `sqlite-vec` is unverified as a loadable extension on Android and ObjectBox is a second storage engine for one feature. **Ceiling:** O(n) per query. Past ~20k chunks, or once scan time shows in `route_log.latency_ms`, replace with ObjectBox HNSW behind the same `search` signature. |
| 6 | Memory, the routing log and the vector cache are JSON/JSONL files, not tables | `ponytail:` on `route_log.dart:RouteLog` — it is appended once per query and read only when tuning, so a line of JSONL costs no schema and no migration. `memory.json` gets the same treatment for a different reason: the "user can see and export everything" requirement wants a small auditable file, and that is what a JSON array already is. **Upgrade path:** sqflite, when aggregate queries stop being something the phone can do by reading the file. |
| 7 | Hand-rolled frontmatter parser (`parser.dart:parseFrontmatter`) instead of `package:yaml` | `ponytail:` — OKF frontmatter is flat scalars plus tag lists. More importantly a real YAML parser *throws* on malformed input, and this path must not: a broken file has to degrade to "all of it is body". **Ceiling:** no nested structures. If OKF ever adds them, wrap `package:yaml` in a try/catch and keep the degrade. |
| 8 | A second, separate embedding GGUF rather than mean-pooling the chat model | A causal chat model mean-pooled into a vector is a poor sentence embedder, and retrieval quality is the entire justification for the vector path. Two models cost RAM and one more setup step; a bad embedder costs every answer. Without one the app degrades to BM25-only and says so in the chat header. |
| 9 | Embeddings run in their own isolate (`embedding_engine.dart:EmbeddingEngine`) | Not a design preference — a binding constraint. `llama_cpp_dart` exposes `getEmbeddings` only on the synchronous FFI `Llama` class, never on the isolate-backed `LlamaParent` the chat path uses. Called inline, embedding a few thousand chunks blocks the UI thread for minutes. |
| 10 | `nGpuLayers = 0` in the embedding isolate too | Same reason as the chat engine: this build of `llama.cpp` has no mobile GPU backend linked in, and the library's default of 99 segfaults on the first layer offload. Duplicated deliberately — the two engines construct their params independently. |
| 11 | Reciprocal rank fusion (`vector_index.dart:reciprocalRankFusion`) instead of a tuned `α·cosine + (1-α)·bm25` blend | An alpha needs per-list score normalisation and a number nobody has evidence for yet. RRF needs neither and is rank-only, which is exactly right for ordering. The spec itself flags its own α as probably wrong for this corpus; RRF removes the parameter rather than guessing it. |
| 12 | The post-retrieval fallback thresholds against raw BM25 / raw cosine, never against the fused RRF score | RRF is rank-only: its top score is `1/61` whether the corpus answered perfectly or not at all, so thresholding it measures how many lists were fused and nothing else. `RetrievalResult.bestLexical` / `.bestDense` are carried alongside the ranking precisely because "nothing actually matched" has to be expressible (`retrieval_service.dart:_isWeak`). |
| 13 | A manual `RAG`/`OKF` choice is never overridden by the fallback | Only `requested == auto` can fall back (`retrieval_service.dart:retrieve`). A switch that silently second-guesses the user is worse than no switch — and the manual positions are the control group the whole Auto experiment is measured against. |
| 14 | Indexing never runs automatically, on app start or otherwise | Embedding a bundle on a phone CPU is minutes of sustained load: a battery and thermal event, not a startup task. `openCorpus` returns `needsEmbedding` for the UI to *offer* ("Reindex now" in Config), and `Corpus.embedAll` takes a `shouldCancel` so the user can stop it mid-pass. |
| 15 | Staleness = content hash mismatch **or** embedding-model mismatch (`bundle.dart:BundleManifest.isStaleFor`) | The content hash is sha256 over sorted `(relpath, file hash)` pairs, so an unchanged bundle does zero embedding work on open. The model name is in the same check because vectors from a different embedder are not comparable — same text, incomparable geometry, silently wrong neighbours. |
| 16 | Vectors are cached to `okf_vectors.json` and validated chunk-by-chunk on load | Re-embedding on every launch would make the app unusable. `Corpus.loadVectorCache` returns false on any length or text mismatch rather than serving vectors that no longer line up with their chunks — a misaligned cache is worse than no cache, because it fails silently. |
| 17 | Two chunks covering ≥60% of a concept are promoted to the whole file (`vector_retriever.dart:kWholeFileThreshold`) | At that point the fragments cost more tokens than the file they came from and read worse. Dedupe and coherence in one rule. |
| 18 | A seed concept is truncated to fit the budget, never dropped; a non-seed is skipped but the walk continues | The seed *is* the answer to the question — dropping it to make room for its neighbours inverts the priority. A too-large neighbour is skipped rather than ending the walk, because a smaller one further out may still fit. The truncation marker's own token cost is subtracted before cutting: a ceiling that the explanation of the ceiling breaks is not a ceiling (`graph_retriever.dart:_truncateToTokens`). |
| 19 | The router's structural-noun vocabulary is `SELECT DISTINCT type`, not a hardcoded list (`bundle.dart:Bundle.types`) | A hardcoded list of "runbook, schema, metric…" is a guess about someone else's notes. Reading the corpus's own frontmatter `type` values means the heuristic adapts to whatever the user actually authored, including vocabulary nobody anticipated. |
| 20 | Router stage 3 (LLM classify) is capped at 800 ms and falls straight through on timeout | A router slower than the retrieval it routes is a failed design. The timeout is not error handling, it is the contract: `routeQuery` drops to the stage-4 default rather than waiting for a phone-speed generation to decide a question retrieval could already have answered. |
| 21 | Every routing decision is surfaced on the answer, with a one-tap "wrong mode, retry as X" | Retrieval that cannot be inspected cannot be trusted, and a router nobody can correct cannot be tuned. The chip shows mode, reason, confidence, latency, item and token counts, seeds, and whether a fallback fired; the retry re-runs the same question in the other mode and records `user_override`. |
| 22 | `route_log.jsonl` exists at all | It is the entire justification for building Auto. After a couple of hundred real queries, `fell_back` and `user_override` say which heuristics in `router.dart` earn their place. Every heuristic there is a guess with a deletion date; this file is what sets it. |
| 23 | The router heuristics ship as the spec's guesses, explicitly labelled as such | Shipping them means the log gets populated with something to measure. Tuning them before there is data would produce a second set of guesses with more confidence and no more evidence. |
| 24 | Memory is rows of text: no fine-tuning, no LoRA, no weight updates | "Learning" that cannot be listed, edited and deleted is not a feature the user can consent to. `memory_fact.dart` is the whole honest scope, and `memory_screen.dart` ships with it rather than after it. |
| 25 | Memory delete is soft (`active = false`), never a hard delete | The decay job deactivates unused facts automatically; if that were destructive the app would be quietly discarding things the user never agreed to lose. Retired facts stay visible behind "Show retired" and restore in one tap. |
| 26 | Extraction parses strictly: malformed JSON writes nothing (`memory_fact.dart:parseExtraction`) | A small model wraps JSON in prose and fences often enough to matter. Taking the outermost `[...]` and discarding anything that does not parse means a failed extraction is a no-op; a lenient parser would let half-parsed garbage into a store the user is expected to trust. |
| 27 | Dedupe on embedding cosine > 0.92, and a fact with no vector is never treated as a duplicate | Without dedupe the store fills with fifty rephrasings of one preference inside a week. Without the second half of the rule, a missing vector would silently merge two genuinely different facts — losing a fact is the worse of the two failures, so the ambiguous case inserts. |
| 28 | Token counting is `length / 3.5`, not a tokenizer (`tokens.dart:kCharsPerToken`) | Every budget in the app is a ceiling. A conservative overestimate costs a little context; an exact count costs a tokenizer round-trip per chunk on a phone. **Ceiling:** the estimate drifts on code, tables and non-Latin text. If a prompt ever overflows the window, this constant is the first suspect. |
| 29 | Degraded is always preferred to failed | No embedding model → BM25-only retrieval. A chunk that fails to embed is skipped, not the pass. A query that fails to embed retrieves lexically. A corrupt `memory.json` loads empty. Every one of these answers the question worse; none of them refuse to answer it. |
| 30 | Cloud inference kept alongside on-device | On-device 1B-class output is weak, and the retrieval work is what is actually being evaluated here. Keeping the cloud engine means retrieval quality can be judged without the generator being the bottleneck. Everything except the model call still runs locally. |
| 31 | Link resolution refuses anything that escapes the bundle root (`parser.dart:extractLinks`) | `../../../etc` in a markdown link is a path-traversal attempt as much as a broken link. Normalising and dropping anything starting `..` makes the correctness rule and the security rule the same line of code. |
| 32 | Cloud engine failures propagate as stream errors, not swallowed retries | `ponytail:` on `cloud_api_engine.dart` — the caller already renders `GenerationError` in the transcript. A retry layer would hide the failure the user needs to see and the network state it implies. |
| 33 | A corrupt LLM library JSON starts empty rather than throwing | `ponytail:` on `llm_library.dart` — unrecoverable stored JSON has no better answer than a fresh list, and blocking app start on it is strictly worse. |
| 34 | The LangChain chat-model adapter carries no fields an engine cannot honour | `ponytail:` on `langchain_chat_model.dart` — options that are accepted and ignored are worse than options that do not exist. Add them when an engine can actually act on them. |
| 35 | The manifest is `okf_manifest.json` in the app documents directory, not `.okf-manifest.json` inside the bundle folder (`knowledge_service.dart:_manifestFile`) | A deliberate deviation from spec §2.1. A folder picked through the system directory picker is not reliably writable under scoped storage, and a manifest that silently fails to write means re-embedding the whole bundle on every launch — minutes of CPU, every cold start, with no visible cause. Keeping it beside `okf_vectors.json` also means the two halves of one cache live or die together. The cost is that the manifest does not travel with the bundle; nothing reads it off-device, so nothing is lost. |
| 36 | Memory extraction runs every 6 answered turns, not at session end (`chat_screen.dart:_extractEvery`) | Extraction is a whole extra LLM call, so it cannot run per turn; but deferring it to teardown means it never runs — a phone kills the process without warning and `dispose` is not a promise. A fixed turn cadence is the only trigger the app reliably reaches. Failures are swallowed on purpose: a missed extraction is invisible, and surfacing it would put an error on a turn that otherwise succeeded. |
| 37 | The memory recency/usage boost is applied to fused scores **before** ranking (`vector_retriever.dart:boostMemory`) | Applied after the sort it would change only the number rendered on the item, which is the one place it does not matter. The boost is passed in as a `MemoryBoost` callback rather than importing the store, so `vector_retriever.dart` stays free of `lib/memory/` and the retrieval tests keep working without one. |
| 38 | The routing log gets an in-app screen (`route_log_screen.dart`), not just a file | `route_log.jsonl` is the only evidence that says which router heuristics earn their place, and a log that has to come off the device with `adb` never gets read. The screen leads with query count, fallback rate and override rate because those three numbers are the whole argument for or against AUTO existing. |
| 39 | Source chips open the raw markdown, unrendered (`source_screen.dart`) | A citation that cannot be opened is decoration. Showing the raw file rather than a rendered view is the point: the question a reader has is "what was the model actually given", and rendering hides exactly the frontmatter and link syntax that answer it. |
| 40 | The imported Claude Design canvas is checked into the repo at `design/Pocket RAG.dc.html`, and it replaced the visual system wholesale | `claude-design-prompt.md` asked for six screens plus a component sheet; the canvas came back with three artboards — CHAT — DARK (INTERACTIVE), CHAT — LIGHT VARIANT, COMPONENT SHEET — so Source, Routing log, Memory and Onboarding exist in code without a designed counterpart and were restyled by hand from the same tokens. Keeping the canvas in the repo is what makes that gap checkable instead of a memory: the artboards are the reference the theme is read against. It is design input, not a build input — nothing compiles it. |
| 41 | `AppColors` became global getters over a mutable `_palette`, not `Theme.of(context)` (`app_theme.dart`) | Every screen already read `AppColors.x` statically from helpers that take no `BuildContext`. Threading a context through `appBody`, `appMono`, `appSectionLabel` and every widget helper would have been a larger diff than the theme toggle itself. **The cost is real and paid twice:** `const` had to be stripped from ~21 widget expressions in `lib/ui/` because a getter is not a compile-time constant, and nothing under the root re-reads the palette on its own — `main.dart:ThemeScope` exists solely to `setState` the whole app when the palette swaps. **Ceiling:** the moment a second surface needs a different palette at the same time (a preview pane, a print view), this global is wrong and `Theme.of(context)` is the upgrade. |
| 42 | One accent colour (#5B8DEF dark / #3D6FD9 light) and still no semantic colour | The previous system had no accent at all (see the rewritten `design_theory.md` Part 3). The design introduces exactly one, and it is spent only on state that means "this is what is active or what happens next": the selected mode segment, the send button, the index progress bar, the mode chip's label, the retry control. There is still no red for errors and no green for success — an error is words, not a hue — so the UI stays legible under colour-vision deficiency. A second accent would immediately require a rule about which means what, and there is no such rule. |
| 43 | The palette is resolved in `main()` before `runApp`, not after the first frame (`main.dart`) | `EngineSettings.load` is already awaited there for other reasons, so reading `themeMode` costs nothing extra. Doing it in a `FutureBuilder` after the first frame would paint dark and repaint light on every cold start for a light-theme user — a visible flash, on every launch, forever, to save one `await`. |
| 44 | Non-markdown extraction is `package:archive` plus a regex tag sweep, not an Office library (`okf/extractors.dart`) | `ponytail:` at the site. `.docx` / `.pptx` / `.xlsx` are ZIPs of XML, and only a handful of tags in each carry visible text (`w:t`, `a:t`, `t`/`v`). `archive` was already needed and is a few lines away from the text; a full Office library is a large dependency for a flat string. `package:xml` is not a direct dependency either, so even the parse is a sweep. **Ceiling, and it is not small:** `.xlsx` comes out as a flat text stream with row and column structure lost, so a citation can quote a number without the header that gives it meaning. **Upgrade path:** `package:xml` and real cell addressing, if a spreadsheet corpus ever matters. |
| 45 | PDF and image rows are shown in Config greyed with "not supported offline", rather than hidden or togglable (`config_screen.dart:_kFileTools`) | Both are registered in `textExtractors` and both return null: PDF needs a real parser (font maps, content-stream operators, encodings) and image OCR needs ML Kit or Tesseract plus a platform channel per platform — neither is a dependency this app carries. A toggle that indexes nothing is the worst of the three options, because the user cannot tell it failed. Hiding the rows is the second worst: the design promises those formats, and silence reads as "not thought about". A visible disabled row with a reason states the gap. |
| 46 | `SkillState` stores enabled **slugs**, never skill bodies (`agents/skill_state.dart`) | The skill's name, description and body already live in `InstructionLibrary` as markdown on disk. Copying any of it into preferences would create a second copy that can disagree with the first. `load` also drops a slug the library no longer knows, because a deleted slug later reused by an unrelated skill would come back switched on and quietly inject instructions the user never enabled. |
| 47 | `AgentRegistry` mirrors `LlmLibrary`'s idioms exactly rather than inventing its own (`agents/agent_registry.dart`) | Immutable value type, `add`/`update`/`remove`/`setActive`, one JSON blob in `SharedPreferences`, corrupt JSON logs and starts empty (#33). Two persistence shapes for two lists of user-defined things is two migration stories. `AgentEntry.modelId` is a reference into `LlmLibrary`, never a copy of the model config, so re-pointing an endpoint does not leave stale duplicates on every agent; removing the active agent clears `activeAgentId` rather than promoting a neighbour, because silently running a persona the user did not select is worse than having none. |
| 48 | An agent-logic persona is **prefixed** to `kSystemPrompt` by default, and only replaces it on an explicit `prompt: replace` (`agents/agent_logic.dart:systemPrompt`) | `kSystemPrompt` carries the citation rule and the "say plainly when the context does not contain the answer" rule — the two sentences the whole inspection thesis rests on. A persona that quietly replaced them would turn a grounded assistant into a confabulating one, and the change would be invisible in the UI. Replacing stays possible because someone will genuinely want it; it just has to be typed. |
| 49 | Agent-logic routing rules enter the router as an optional stage-0 `ForcedRoute` hook (`router.dart`) | A rule the user wrote by hand beats every heuristic this app guessed (#23), so it runs before stage 1 and returns `reason: 'agent-logic'` — which means the route log can measure hand-written rules the same way it measures ours. It is a `typedef RetrievalMode? Function(String)` rather than an `AgentLogic` parameter so `lib/retrieval/` never imports `lib/agents/`, keeping the router tests free of the file system. A rule returning `auto` is treated as no opinion and falls through to the heuristics. |
